# 蜕变记 · Pet Transform —— 项目详细分析

本文从架构、数据、关键模块、业务逻辑、安全与工程化六个维度做完整剖析，供答辩与代码走读使用。

---

## 1. 总体架构

### 1.1 在线优先的混合分层

```
┌─────────────────────────────────────────────┐
│  UI 层   pages / view / components            │  声明式 ArkUI
├─────────────────────────────────────────────┤
│  service 层   业务逻辑                          │  Auth / Pet / Schedule / Stats / Session …
├─────────────────────────────────────────────┤
│  repository 层   仓储（方法名与数据源无关）        │
│     ├── ApiClient ──► 云端 REST                │  pet/feed/weight/substrate/user/photo
│     └── relationalStore ──► 本地 SQLite        │  molt/env/todo/video
└─────────────────────────────────────────────┘
                     │
            云端 PHP 后端（与微信小程序共享）
            前端控制器 + PDO/MySQL + JWT + SMTP
```

**设计原则**：UI 永远不直接访问数据源。每个 `*Repository` 对外暴露统一的方法名（`findByUser/findById/create/update/remove/listByPet …`），无论内部走云端 HTTP 还是本地 SQLite。这样：

- service / UI 代码**与数据来源无关**；
- 未来把"蜕皮/环境/待办/视频"任意模块迁上云，只需替换对应仓储实现，service 与页面零改动。

### 1.2 为什么是"混合"而非全上云或全本地

- 全本地：无法多端共享（鸿蒙 + 微信小程序看同一份数据是硬需求）。
- 全上云：后端目前没有蜕皮/环境/待办/视频的表，且视频上云成本高。
- 折中：**已有后端表的核心数据上云**，**后端暂缺的模块留本地**，用统一仓储接口把差异藏起来。

### 1.3 启动流程

`EntryAbility.onWindowStageCreate` 依次 `await`：
`Database.init`（建本地 4 表）→ `SessionStore.init`（读 preferences）→ `SessionStore.restoreToAppStorage`（镜像到 AppStorage）→ `ThemeService.init`，最后加载 `pages/Index`。
`Index` 读 `AppStorage` 的 `SESSION_USER_ID`（= openid），非空进主页，空进登录页。

## 2. 数据模型与标识符

### 2.1 标识符统一为字符串

- 云端主键：32 位 hex `_id`，用户标识 `openid`（微信用户 `oq_...`，鸿蒙用户 `hm_...`）。
- 端上所有 `id/userId/petId`、`AppStorage` 的 `SESSION_USER_ID`/`CURRENT_PET_ID` 均为 **string**（空串 = 无）。
- 本地附属表（molt/env/todo/video）自身主键仍是自增 number，但 `pet_id`/`user_id` 外键是 **string（TEXT 列）**，以对接云端标识。

### 2.2 字段映射（DTO 层）

云端 JSON 字段名与端上模型不一致，由仓储做映射，例如：

| 模型字段 | 云端字段 |
|---|---|
| `Pet.birthDate` | `arrivalDate` |
| `FeedLog.date` | `feed_date` |
| `WeightLog.date` | `record_date` |
| `SubstrateLog.substrateType` | `sub_type` |
| `Photo.date` | `taken_at`（截取前 10 位日期） |

### 2.3 本地表（4 张）

`molt_log`、`env_log`、`todo`、`video`。视频表 `video(id, user_id, pet_id, uri, caption, created_at)`，`uri` 存沙箱内绝对路径。

### 2.4 云端表关键列（节选）

- `user_info`：`openid`、`username`、`password_hash`、`nickname`、`avatarUrl`、`email`(可空、唯一)。
- `pet_photos`：`_id`、`pet_id`、`url`、`thumb_url`、`caption`、`taken_at`、`length_cm`(可空)。
- `email_codes`：`email`、`code`、`purpose`、`expires_at`、`used`、`created_at`。

## 3. 网络层（ApiClient）

- 基于 `@kit.NetworkKit` 的 `http`，封装 `get/post/put/del`，统一返回 `Result<T>`。
- 自动附 `Authorization: Bearer <token>`（token 取自 SessionStore）。
- 错误归一：`401` 清会话并返回 `err_unauthorized`；`5xx` 返回 `err_server`；`4xx` **透传后端中文消息**（如"验证码错误或已过期"）。
- `postPublic()` 用于登录/注册/找回，401 不触发会话失效而是透传后端消息。
- `uploadImage()`：手动拼装 `multipart/form-data` 包体（head + 文件字节 + tail），走 http 直接拿 `{url, thumb}` JSON 响应。TLS 证书由系统 CA 校验（API 12+ 无需手动提供 CA）。

## 4. 关键模块剖析

### 4.1 账号体系
- **注册**：用户名 + 邮箱 + 验证码 + 密码 → `/auth/register`；服务端校验验证码、唯一性，生成 `hm_` 开头 openid，`password_hash` 入库，返回 JWT。
- **登录**：`/auth/login-app`，`password_verify` 校验。
- **找回密码**：`ForgotPasswordPage` 收集 用户名+邮箱+验证码+新密码 → `/auth/reset-password`；服务端校验"用户名与邮箱匹配同一账号"+ 验证码，再写新 `password_hash`。
- **验证码**：`EmailCodeField` 组件复用收码逻辑（发送按钮 + 60 秒倒计时）；验证码服务端生成/存储/校验，限频、过期、一次性。

### 4.2 成长相册（云端）
- 选图 → `ApiClient.uploadImage` 上传 → `PhotoRepository.create` 记录到云端 `pet_photos`。
- 列表 `listByPet` 前端兜底排序：**最新日期在最上**，同日按创建时间倒序。
- **高清查看器**：全屏半透明黑底 + `PinchGesture` 双指缩放（0.5–6×）+ `PanGesture` 拖动 + 双击复位（带贝塞尔曲线动画），点空白关闭。

### 4.3 成长瞬间（主页轮播）
- `HomeTab` 汇总名下所有宠物的相册照片，按日期取最新 10 张，用 `Swiper(autoPlay, interval, loop, indicator)` 自动轮播；点图设置 `CURRENT_PET_ID` 并跳相册查看。

### 4.4 成长视频（本地）
- 选视频 → `fileIo.copyFileSync` 复制进沙箱 `filesDir/videos/` → 本地 SQLite 记录绝对路径。
- 用 ArkUI 内置 `Video({ src })` 组件 `.controls(true)` 播放。删除时同时移除沙箱文件与记录。
- 不上云：契合作业场景、零后端成本；模型命名 `PetVideo` 以避开与内置 `Video` 组件重名。

### 4.5 头像
- `PetAvatar` 组件按内容自动判别：`http/file/data:` 开头当图片渲染，否则当 emoji。
- 编辑页改为**点击头像才展开选择面板**（上传照片 + emoji），上传走云端拿 URL。

### 4.6 图表
- 体重趋势、温度趋势、近 7 天喂食柱状图，全部用原生 `Canvas` 手绘，无第三方库。

## 5. 核心业务逻辑：动态排程

```
next_feed_date     = 实际喂食打卡日 + feed_interval
next_substrate_date = 实际换料打卡日 + sub_interval
```

- 由 `ScheduleService.nextFeedDate/nextSubstrateDate` 经 `DateUtil.addDays` 计算。
- 漏打卡的天数随下次打卡自动纠偏，**不堆积欠账**——比固定日历更贴近真实养护。
- 紧急度（`Urgency`）由下次日期相对今天得出：今日（橙）/ 逾期（红）/ 未来（绿），驱动首页排序与色标。

## 6. 后端（PHP）

- **前端控制器**：`index.php` 用正则路由表 `[METHOD, pattern, file, func]`，命中后 `require` 对应文件并调用 handler；非公开路由先 `require_auth()` 校验 JWT。
- **鉴权**：JWT HS256，`openid` 入 payload，30 天过期；公开白名单含登录/注册/找回/微信回调。
- **数据隔离**：所有按 `openid` 过滤；`assert_pet_owned` 防跨用户读写。
- **邮件**：`lib/mailer.php` 用 `stream_socket_client('ssl://smtp.qq.com:465')` 手写 SMTP（EHLO → AUTH LOGIN → MAIL/RCPT/DATA），正文整体 base64 规避点行与行长问题；配置读自 `.env`。
- **增量原则**：邮箱相关全部是"加可空列 + 新表 + 新路由"，且把会被 nginx `fastcgi_intercept_errors` 拦截的 404 改为 400，保证返回 JSON 而非 HTML。

## 7. 安全与工程化

- **密码**：服务端 `password_hash`/`password_verify`（自带盐）；端上不存明文/哈希。
- **密钥**：SMTP 授权码、DB 密码、JWT 密钥只在服务器 `.env`，从不进客户端、从不进公开仓库（提交前 grep 校验）。
- **验证码**：服务端生成校验、60s 限频、10 分钟过期、命中即作废（防重放）。
- **生产保护**：改动先备份；**先迁移、再部署**（避免代码引用尚不存在的列导致现网 500）；改完做回归（登录/受保护接口仍 401 而非 500）。
- **编译校验**：headless `hvigorw --no-daemon assembleHap`。
- **测试**：`LocalUnit.test.ets` 覆盖日期/排程/校验。
- **规范**：`code-linter.json5`，设计令牌（`$r('app.float/color.…')`）避免硬编码，路由/存储键集中在 `RouteConstants`/`StorageKeys`。

---

## 8. 局限与改进

- 当前为**纯在线优先**，无离线缓存；弱网体验可加本地缓存 + 后台同步。
- 验证码由客户端触发发送，服务端虽限频，仍可加图形验证码进一步防刷。
- 视频仅本地，未多端共享。
- 蜕皮/环境/待办尚未上云，数据源未完全统一。
