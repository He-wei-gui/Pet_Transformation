# 蜕变记 · Pet Transform —— 答辩一问一答

> 面向老师可能提出的问题，按"怎么做出来的、为什么这么做、细节追问"整理。每条都给出可直接照说的答案。

---

## 一、选题与整体

**Q1：这个项目是做什么的？为什么选这个题？**
A：是一款基于 HarmonyOS（ArkTS/ArkUI）的爬行宠物成长记录应用。选它是因为爬宠养护有普通宠物 App 不覆盖的痛点：喂食/换底材有固定周期但漏一次就乱、需要记录蜕皮和温湿度 UVB、而且我希望手机端和微信小程序端能看同一份数据。所以做了一个多端共享、爬宠专属的记录系统。

**Q2：整体架构是怎样的？**
A：分四层——UI（页面/组件）→ service（业务逻辑）→ repository（仓储）→ 数据源。数据源是"在线优先的混合"：核心数据（宠物/喂食/称重/换料/用户/相册）走云端 PHP 后端做多端共享，后端暂时没有的模块（蜕皮/环境/待办/视频）存本地 SQLite。关键是仓储层方法名跟数据源无关，所以 UI 和 service 不用关心数据到底来自云还是本地。

**Q3：为什么不全部上云或全部本地？**
A：全本地没法多端共享，这是硬需求；全上云的话后端目前没有那几个模块的表、而且视频上云成本高。所以折中：有后端表的核心数据上云，没有的留本地，用统一的仓储接口把差异藏起来，以后哪个模块要上云只改仓储实现，UI 不动。

## 二、客户端（ArkTS / ArkUI）

**Q4：ArkUI 的状态管理你用了什么？**
A：V1 装饰器：组件内状态用 `@State`，父子传值用 `@Prop`/`@Link`，跨页面/全局共享用 `AppStorage`（比如当前登录的 openid、当前选中的宠物 id）。`@Watch` 监听变化触发刷新。

**Q5：页面间怎么跳转和传参？**
A：用 `@ohos.router` 按 URL 跳转，URL 常量集中在 `RouteConstants`，每个可跳转页面还要在 `main_pages.json` 登记。跨页要传的标识（如选中宠物）通过 `AppStorage` 的 `CURRENT_PET_ID` 传递，而不是硬编码字符串。

**Q6：图表是用什么库画的？**
A：没有用第三方库，全部用原生 `Canvas` 手绘——体重趋势曲线、温度趋势、近 7 天喂食柱状图都是自己算坐标、连线、画柱子。这样零依赖、可控。

**Q7：相册的"放大查看"是怎么实现的？**
A：全屏盖一层半透明黑底，中间放图片，绑了一个并行手势组：`PinchGesture` 做双指缩放（限制 0.5 到 6 倍）、`PanGesture` 做拖动、`TapGesture(count:2)` 双击在原大小和 2.5 倍间切换并带贝塞尔曲线动画，点空白处关闭。缩放和位移分别用 `.scale()` 和 `.translate()` 应用到图片上。

**Q8：主页的照片轮播怎么做的？**
A：用 ArkUI 内置的 `Swiper` 组件，开 `autoPlay`、设 `interval` 间隔、`loop` 循环、`indicator` 指示点。数据是把名下所有宠物的相册照片合并、按日期取最新 10 张喂给它，点某张就跳到那只宠物的相册。

**Q9：视频播放怎么做的？为什么存本地？**
A：用 ArkUI 内置的 `Video` 组件，`src` 给本地文件路径、`.controls(true)` 显示播放控件。存本地是因为作业场景要轻量、且后端没有视频存储；流程是用 `PhotoViewPicker` 选视频，再用 `fileIo.copyFileSync` 复制到应用沙箱 `filesDir/videos/`，把绝对路径存进本地 SQLite。复制到沙箱是为了避免选择器返回的临时 uri 之后失效。注意我的模型类叫 `PetVideo`，是为了不和内置的 `Video` 组件重名。

**Q10：本地数据库怎么用的？**
A：用 `@kit.ArkData` 的 `relationalStore`，单例持有 `RdbStore`，启动时 `init()` 建表。本地只有 4 张表：蜕皮、环境、待办、视频。用 `RdbPredicates` 做条件查询、排序。轻量的会话和设置用 `preferences` 键值存。

## 三、网络与后端

**Q11：客户端怎么和后端通信？**
A：封装了一个 `ApiClient`，基于 `@kit.NetworkKit` 的 http，提供 `get/post/put/del`，自动带 `Authorization: Bearer <token>`，统一返回 `Result<T>`。错误归一处理：401 清会话、5xx 返回通用错误、4xx 把后端的中文消息透传出来显示。

**Q12：图片是怎么上传的？**
A：后端要 `multipart/form-data`，我没有用第三方库，而是手动拼包体：表单头部 + 文件字节 + 结尾边界拼成一个 `Uint8Array`，作为 `extraData` 用 http POST 上去，直接拿回 `{url, thumb}`。

**Q13：后端是什么技术？**
A：PHP，一个前端控制器 `index.php` 用正则路由表分发；数据库用 PDO + MySQL；鉴权用 JWT（HS256）；密码用 PHP 的 `password_hash`/`password_verify`。部署在阿里云，用宝塔面板管理。这套后端是和微信小程序共享的。

**Q14：多端怎么共享同一份数据？**
A：后端按 JWT 里的 `openid` 做数据隔离。鸿蒙账号登录后拿到的 token 也携带 openid；我还把鸿蒙账号绑定到了同一个微信 openid 上，所以两端登录后看到的是同一份数据。

## 四、核心业务逻辑

**Q15：喂食提醒的日期是怎么算的？这是这个项目的核心吧？**
A：对，核心是"动态排程"：下一次计划日期 = 实际打卡日期 + 间隔天数。比如你今天喂了、间隔 3 天，那下次就是今天 +3。好处是漏打卡不会堆积欠账——你晚了几天，下次还是从你实际打卡那天重新算。紧急度根据下次日期相对今天判断：今天到期是橙色、逾期是红色、还没到是绿色，首页就按这个排序和标色。

**Q16：紧急度和首页排序具体怎么联动？**
A：每只宠物的喂食/换料生成一条 checklist 条目，算出 `Urgency`（今日/逾期/未来）。首页"今日"视图只显示逾期和今日的，"全部"显示所有；排序把逾期、今日排在前面。

## 五、邮箱验证码与找回密码（这次新增）

**Q17：注册的邮箱验证码是怎么实现的？**
A：客户端填邮箱点"发送验证码"，调后端 `/auth/send-code`；后端生成 6 位码、存进 `email_codes` 表（带过期时间和一次性标记），然后通过 SMTP 发到邮箱。注册时把邮箱和验证码一起提交，后端校验通过才创建账号。客户端那个发送按钮有 60 秒倒计时防止狂点。

**Q18：找回密码的完整流程？**
A：用户在找回页填 用户名 + 邮箱 + 收到的验证码 + 新密码，调 `/auth/reset-password`。后端先确认这个用户名和邮箱是同一个账号、再校验验证码，都过了才把新密码用 `password_hash` 写回去。

**Q19：验证码发邮件你是怎么发的？为什么放服务端？**
A：服务端用 PHP 的 `stream_socket_client` 连 `ssl://smtp.qq.com:465`，手写 SMTP 协议：先读 220、EHLO、AUTH LOGIN 把用户名密码 base64、然后 MAIL FROM / RCPT TO / DATA，正文整体 base64 避免特殊字符问题。放服务端是出于安全：QQ 的授权码是密钥，如果放客户端，App 被反编译就泄露了；放服务端的 `.env` 里才是密钥该待的地方，也绝不进 Git 仓库。

**Q20：验证码安全吗？怎么防刷、防重放？**
A：三重：60 秒限频（同邮箱同用途 60 秒内只能发一次）、10 分钟过期、命中即作废（用过的码标记 used，不能再用）。验证码的生成和校验都在服务端，客户端只是触发。

## 六、安全与工程化

**Q21：密码是怎么存的？明文吗？**
A：绝不明文。密码在服务端用 `password_hash`（默认 bcrypt，自带盐）哈希后存，校验用 `password_verify`。客户端不保存密码，只保存登录后的 JWT token。

**Q22：你怎么保证改后端不影响正在跑的微信小程序？**
A：所有改动都是增量的——只"加可空列、加新表、加新路由"，不动任何现有列和逻辑，小程序根本不会调用这些新接口。而且我严格按"先备份、先做数据库迁移、再部署引用新列的代码"的顺序；有一次我顺序反了（先传了引用 email 列的代码、列还没建），意识到会让小程序的 /user 接口 500，立刻回滚保护现网，等迁移完再重新部署。改完还做了回归：登录、受保护接口该返回 401 的仍然是 401 不是 500。

**Q23：遇到过什么坑？怎么解决的？**
A：举几个：① 服务器 nginx 开了 `fastcgi_intercept_errors`，会把我返回的 404 JSON 替换成 nginx 的 HTML 404 页，导致前端拿不到中文提示——我把这些用户校验错误改成 400 就正常了。② 邮箱列加了唯一索引，但没邮箱的用户如果存空字符串会互相冲突（多个空串违反唯一），所以后端把空邮箱统一存成 NULL（多个 NULL 不冲突）。③ 主键类型，本地是自增数字、云端是 hex 字符串，统一改成字符串解决。

**Q24：怎么做国际化和主题？**
A：所有文案放资源文件，中文在 `resources/base`、英文在 `resources/en_US`，成对维护。校验和服务层返回的是"资源键名"，页面再用 `I18n.t` 解析成当前语言。颜色、间距、字号都用设计令牌 `$r('app.color/float.…')`，浅深色各一套色值，不硬编码。在"我的"页可一键切换语言和主题并持久化。

**Q25：怎么验证代码是对的？**
A：三方面：① 用 DevEco 自带工具链做 headless 编译检查，每改一批就 `hvigorw assembleHap` 编译一次；② 纯逻辑写了单元测试，覆盖日期工具、排程算法、各种校验；③ 后端用 curl 实测——验证码真发出去能收到、限频/格式/不匹配都返回正确的码和中文消息、回归测试确认小程序链路没受影响。

**Q26：如果让你继续做，会加什么？**
A：① 登录态下直接改密码的接口；② 视频上云做多端共享；③ 把蜕皮/环境/待办也迁上云，彻底统一数据源；④ 加离线缓存和后台同步，改善弱网体验；⑤ 发验证码再加个图形验证码进一步防刷。

## 七、可能的代码追问

**Q27：`Result<T>` 是干什么的？**
A：是统一的结果包装，service 和 repository 不向 UI 抛异常，而是返回 `Result.ok(data)` 或 `Result.fail(messageKey)`，UI 统一判断 `success` 再决定显示数据还是错误提示。让错误处理一致、可控。

**Q28：为什么标识符全用字符串？**
A：因为云端主键是 32 位十六进制字符串、用户是 openid，本地原来是自增数字。两边不统一会到处类型报错，所以全端统一成字符串，空串代表"无"。本地附属表自身主键还是数字，但外键 pet_id/user_id 改成 TEXT 存云端的字符串 id。

**Q29：启动时做了哪些初始化？顺序为什么重要？**
A：在 `EntryAbility` 里按顺序 await：先初始化本地数据库、再恢复会话（从 preferences 读 openid/token 镜像到 AppStorage）、再初始化主题，最后才加载首页。顺序重要是因为首页要读 AppStorage 里的登录态来决定去登录页还是主页，会话必须先恢复好。

**Q30：组件复用举个例子？**
A：`EmailCodeField` 把"邮箱输入 + 验证码输入 + 发送按钮 + 60 秒倒计时"封装成一个组件，注册页和找回密码页都用它，只用 `purpose` 参数区分是注册还是找回。`PetAvatar` 也复用，自动判断是图片 URL 还是 emoji 来渲染。
