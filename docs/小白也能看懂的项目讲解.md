# 蜕变记 · 小白也能看懂的项目讲解

> 这份文档不用任何编程基础也能看懂。目标是：看完之后，你能用自己的话把"这个项目是什么、它怎么跑起来的、每一块在干嘛"讲清楚。
> 读法：从头往下看就行，遇到的每个名词都会先用生活里的东西打比方。

---

## 〇、先用一句话说清楚

**这是一个手机 App，专门帮养"爬宠"（守宫、蜥蜴、蛇这类爬行动物）的人记录宠物的成长**：什么时候喂食、什么时候换垫材、体重多少、蜕了几次皮、拍的照片和视频……都记在里面，而且**手机和微信小程序两端看到的是同一份数据**。

App 的名字叫「蜕变记」——爬宠会"蜕"皮、会成"变"长，我们帮你"记"录，合起来就是蜕变记。

---

## 一、几个最基础的概念（先打地基）

为了看懂后面的内容，先认识几个词。都用生活里的例子解释：

### 1. App（应用）= 手机里那个图标点开的东西
就是你手机上点一下能打开、能操作的程序。我们做的就是一个 App。

### 2. 前端 / 后端 = "店面" 和 "后厨"
- **前端**：你眼睛能看到、手能点的部分。按钮、文字、图片、页面——就像餐厅的**店面和菜单**，是给客人看的。
- **后端**：你看不到、藏在服务器里的部分。负责存数据、算逻辑——就像餐厅的**后厨和仓库**，客人看不见但很重要。

这个项目：手机 App 是前端，藏在网上的一台电脑（服务器）是后端。

### 3. 服务器 = 一台永远开着、连着网的电脑
普通电脑你关机就没了；服务器是租来的、24 小时开机、谁都能通过网络访问的电脑。我们的后端就跑在阿里云租的一台服务器上。

### 4. 数据库 = 一个超级有条理的大表格
把它想象成 Excel 表格，但更强大：一行是一条记录，一列是一个字段。比如"宠物表"里，每一行是一只宠物，列有名字、品种、生日……数据库就是专门用来**存这些表格、并且能快速查找**的工具。

### 5. 云端 / 本地 = "存在网上" 还是 "存在你手机里"
- **云端**：数据存在那台服务器上。好处是换个设备登录还能看到。
- **本地**：数据存在你手机自己的存储里。好处是不用网也能用，但只有这台手机看得到。

我们的项目**两种都用**（后面会讲为什么）。

### 6. 账号 / 登录 / Token = "会员卡" 和 "进门手环"
- 你注册账号 = 办了张会员卡。
- 你登录 = 出示会员卡，前台确认是你本人。
- 确认之后，后端发给你一个**Token（令牌）**，就像游乐园进门给你戴的**手环**。之后你每做一件事，App 都会亮一下这个手环，后端一看手环就知道"哦是你，放行"，不用每次都重新输密码。

## 二、打开 App 会经历什么（用户视角走一遍）

1. **第一次用**：你看到登录页 → 点"去注册" → 填用户名、邮箱、密码。
2. **邮箱验证**：点"发送验证码"，你的邮箱会收到一封带 6 位数字的邮件，把数字填回去，证明这邮箱是你的。
3. **注册成功**：自动进入主页。
4. **主页**：最上面是一个会**自动翻页的照片横幅**（你给宠物拍的照片轮流展示），下面是"今日待办"——今天该喂哪只、该给哪只换垫材。
5. **管理宠物**：可以加宠物、设头像（用表情符号或上传一张照片）、记体重（还能看一条体重曲线图）、记喂食/换料/蜕皮/温湿度。
6. **相册**：上传照片，点开能像看大图一样**两根手指放大缩小、拖动**。
7. **视频**：在"我的"里有"成长视频"，能上传一段视频并播放。
8. **忘记密码**：登录页点"忘记密码"，填用户名和邮箱，邮箱收验证码，就能设个新密码。

整个过程你不用懂任何技术，就是点点点。下面讲"点一下的背后发生了什么"。

## 三、点一下背后发生了什么（核心原理）

举个最典型的例子：**你新增了一只宠物，点了"保存"**。背后是这样一条流水线：

```
你点保存
   │
[前端 App]  把你填的名字、品种打包成一段文字
   │  （顺便亮一下你的"手环"Token，证明是你）
   ▼
通过网络发给 →  [后端服务器]
   │
[后端]  检查手环 → 确认是你 → 把这只宠物存进"数据库"那张大表格里
   │
   ▼
回一句"存好了，这只宠物的编号是 xxx"
   │
[前端 App]  收到后刷新页面，列表里就出现了这只宠物
```

这就是几乎所有操作的套路：**前端收集你的输入 → 带着手环发给后端 → 后端验证身份、存/取数据库 → 把结果返回 → 前端把结果显示出来。**

这种"前端发请求、后端回结果"的约定，行话叫 **API**（你可以理解成**点菜的菜单**：前端照着菜单点"我要新增宠物"，后端照着菜单做好端回来）。

## 四、为什么数据一半在云、一半在手机？（这个项目最有特点的地方）

这是答辩最容易被问、也最值得讲的点。

**背景**：这个 App 要和一个**微信小程序**共享数据——你用手机 App 加的宠物，在微信小程序里也要能看到。

- 要做到"两端看同一份数据"，数据就必须存在**云端**（都去同一台服务器拿）。
- 但是云端后端目前**只准备好了一部分功能的"表格"**：宠物、喂食、体重、换料、用户、相册——这些有云端表格，所以**存云端**。
- 还有几样后端暂时没做表格：蜕皮、温湿度、待办、视频——这些就先**存手机本地**。

所以是个**"混合"方案**：有云端表格的存云、没有的存本地。

**那 App 怎么不乱？** 这里有个聪明的设计：我们在前端和数据之间加了一层"中间人"（行话叫**仓储层 Repository**）。App 要数据时，只对这个中间人说"给我这只宠物的喂食记录"，**至于这数据是去云端拿还是从手机本地拿，中间人自己处理，App 不用关心**。

打个比方：你在公司让**前台**帮你取一份文件，你不用管这文件是在楼下档案室还是要打电话叫快递从总部寄来——前台搞定，你只管拿到文件。以后哪天"蜕皮记录"也搬上云了，只要改一下前台的取件方式，你（App 页面）完全不用动。

## 五、各个功能块分别在干嘛（逐个拆开）

### 1. 账号与登录
- 注册时密码**不会明文存**。后端会把密码"打乱加密"后再存（行话叫**哈希**，可以理解成把密码搅成一锅没法还原的糊糊；但同样的密码搅出来的糊糊一样，所以能用来核对）。这样就算数据库被偷看，也看不到你真实的密码。
- 登录成功后发"手环"Token，之后免密通行。

### 2. 邮箱验证码 + 找回密码
- **为什么要验证码**：证明你填的邮箱真的是你的（你能收到那封信）。也为了"忘记密码"时有办法找回。
- **怎么发邮件**：后端连上 QQ 邮箱的发信服务器，把验证码发出去。发信需要一个"授权码"（相当于让后端代你发信的专用钥匙）。**这把钥匙只放在服务器里，绝不放进手机 App**——因为 App 能被人拆开看代码，钥匙放进去就等于泄露了。
- **防止被刷**：同一个邮箱 60 秒内只能发一次、验证码 10 分钟过期、用一次就作废。

### 3. 今日待办 + 动态提醒（最核心的业务逻辑）
- 爬宠喂食、换垫材有周期（比如"每 3 天喂一次"）。
- 关键规则：**下次该喂的日期 = 你实际喂的那天 + 间隔天数**。
- 好处：假设你晚了两天才喂，系统不会把欠的两天累加成"欠债"，而是**从你实际喂的那天重新开始算**下一次。这比死板的固定日历更贴近真实养宠。
- 然后用颜色提醒你：今天该做的标橙色、已经拖过期的标红色、还没到的标绿色，主页自动把急的排前面。

### 4. 成长相册 + 大图查看器
- 照片上传到云端，多端可见。
- 点开照片能像**看相机相册**那样：两指张开放大、合拢缩小、按住拖动、双击复位、点空白处关闭。这是用手势识别做出来的。

### 5. 主页照片轮播（"成长瞬间"）
- 主页顶部那个会自己翻页的照片横幅，是把你所有宠物**最近的照片**收集起来，每隔几秒自动换一张，点一下就跳进相册。

### 6. 成长视频
- 选一段手机里的视频，App 把它**复制一份到自己的"专属储物柜"**（沙箱，就是这个 App 私有的存储空间，别的 App 碰不到）。
- 复制是为了保险——直接引用相册里的视频，过段时间链接可能失效；复制进自己的储物柜就一直能播。
- 视频**只存本地、不上云**（因为是作业，存本地最省事，也不花服务器存储）。

### 7. 头像、主题、语言
- 头像可以选表情符号，也可以上传自己的照片。
- 可以一键切换**中文/英文**、**浅色/深色**主题，而且记住你的选择。

### 8. 各种图表（体重曲线、喂食柱状图）
- 这些图**没有用现成的图表工具**，是程序自己一笔一画在屏幕上画出来的（算好每个点的位置再连线/画柱子）。

## 六、这个项目用到的"工具"都是什么（技术名词翻译成人话）

| 技术名词 | 人话解释 |
|---|---|
| HarmonyOS（鸿蒙） | 华为的手机操作系统，类似安卓/iOS。我们的 App 跑在它上面 |

| PHP / MySQL | 后端用的编程语言 和 数据库软件。相当于"后厨用的灶具和仓库货架" |
| 服务器 / 阿里云 / 宝塔 | 租来的那台永远开机的电脑 / 租它的公司 / 管理这台电脑的可视化面板 |

| JWT / Token | 登录后发的"进门手环"，证明你是你 |
| 数据库 / 表 / 字段 | 超级表格 / 一类东西的表 / 表里的一列（比如"宠物名"） |
| 仓储层 | 前端和数据之间的"前台/中间人"，帮你取数据，你不用管数据在哪 |

| 沙箱 | 每个 App 私有的储物柜，别的 App 进不去 |
| SMTP | 发邮件用的标准方式/协议 |
| Swiper / Video | 鸿蒙自带的"轮播组件"和"视频播放组件"，拿来就能用 |

## 八、一段话总结（背这段就够开口）

> 我们做的是一个鸿蒙手机 App「蜕变记」，帮养爬宠的人记录喂食、换料、体重、蜕皮、照片视频等成长信息。它和一个微信小程序共享数据，所以核心数据存在云端服务器、用账号登录后按身份取；后端还没做的几个模块就先存在手机本地。前端负责界面、后端负责存数据，中间用 API 通信、用 Token 证明身份。最有特点的是两点：一是"一半数据在云一半在本地，但用一个中间层把差异藏起来，App 不用关心数据来源"；二是喂食提醒用"下次=实际打卡日+间隔"的动态规则，漏喂了也不会累积欠债。安全上，密码加密存、邮箱发验证码且发信钥匙只放服务器不进 App。
